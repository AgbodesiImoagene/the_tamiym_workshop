## Design review

Recorded 2026-11-21, before implementation. Decisions by the user the same day: **option A** (no generated export file; preview, originals and positions) and **a JSON copy on the order item**.

### Finding confirmed on current `main`

- `OrderItem` only stores `designId` (`apps/api/prisma/schema.prisma`, model `OrderItem`). `Design.designData` is editable, so a later edit changes what the admin would read: the invariant "later edits never change what an order prints" does not hold today.
- The admin order detail (`apps/admin/app/admin/orders/[id]/page.tsx`) shows `Design: <name>` and nothing else. `findOneForAdmin` only selects `design: { id, name }`.
- Already in place and reused: `GET /design-assets/:id/link` (short-lived signed link, admins may read any asset, TTW-099) and `GET /design-assets/:id/file` (authenticated bytes).

### Decisions

1. **Freeze at order time.** New nullable column `OrderItem.designSnapshot` (Json, migration generated by the Prisma CLI). Written in the same transaction as the item, from `toOrderItemCreateData`'s callers (standard and campaign orders). Versioned (`version: 1`). Never updated afterwards. Items without a design keep `null`. Images are not copied: an upload never changes once stored. Correction found at review: a `DesignAsset` is deleted with its owner (`onDelete: Cascade`), so an account erasure would remove the originals of a paid order. See "Open risks" below.
2. **Content of the snapshot.** Design id and name, then for every view that holds layers: view key and name, product view id, print area (x, y, width, height as stored), and each layer reduced to an allowlist (image: `designAssetId`, position, scale, angle, flips; text: text, font, size, colour, position, scale, angle). Nothing else from the Fabric JSON is copied.
3. **Admin response.** `GET /admin/orders/:id` adds `items[].printFiles` built from the snapshot only (never from the live design) plus, per image layer, the file facts read from `MediaAsset` (mime, bytes, pixel size) and two stable paths: a display preview and the signed-link endpoint. Response DTO is explicit and documented in Swagger. Customer routes never include it.
4. **Preview.** Drawn in the admin browser from the frozen layers as positioned boxes inside the print area (no Fabric in admin, no server rendering). It is a layout preview for the print shop, not the pixel-exact render that TTW-143 will provide for moderators.
5. **Originals.** A button per image calls `GET /design-assets/:id/link?variant=original` on click, so the link is fresh and never stored or logged.

### Risks and mitigations

- Security: only the admin surface returns `printFiles` (existing `@Roles(ADMIN)` guard on `admin-orders.controller.ts`, test that a customer gets 403). Signed links are minted per click, with the existing TTL cap. No file name, link or customer text goes to logs.
- Data: snapshot is bounded by the existing `TOO_LARGE` limit of the design document, and the allowlist drops everything else.
- Old orders: there are no live users yet, so orders created before this change keep `designSnapshot = null`. The admin shows "Print files were not recorded for this item" for them instead of reading the live design.
- Concurrency: the snapshot is read inside the order-creation transaction, so a save racing with checkout yields either the old or the new design, never a mix. Idempotent replays return the existing order and do not write a second snapshot.

### Out of scope here

- A generated PDF/PNG export per face (the user chose option A). To reopen only if the print shop asks.

## Open risks (decide before release, not part of this change)

- **Originals can vanish with the account.** `DesignAsset.owner` is `onDelete: Cascade`. TTW-120 (erase files of deleted accounts) must keep the uploads of designs frozen on a paid order, or the print shop loses them. The admin screen already says "This file is no longer available" instead of failing. Raise it when TTW-120 is designed.
- **Preview is a layout, not a render.** Text ignores the layer width, alignment and wrapping, so a long text can run past its box in the preview. The positions listed next to it are exact. TTW-143 covers the real render.
- **Frozen without a second eligibility check.** The design is read inside the order transaction, but owner, product and moderation status are only checked before the quote (TTW-239). A rejection landing in that short window would still freeze the design.
- **Opening an original** uses an anchor click after the request. A browser that drops the click gesture after an await (Safari) can block the new tab. Not reproduced here.
- **Playwright stands in for storage.** The local seed has no stored object, so the journey answers the preview and the signed-link requests with fixed responses. The real link endpoint is covered by TTW-099 tests only.
