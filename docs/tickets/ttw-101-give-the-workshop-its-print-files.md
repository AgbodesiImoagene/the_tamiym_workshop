## Design review

Recorded 2026-11-21, before implementation. Decisions by the user the same day: **option A** (no generated export file; preview, originals and positions) and **a JSON copy on the order item**.

### Finding confirmed on current `main`

- `OrderItem` only stores `designId` (`apps/api/prisma/schema.prisma`, model `OrderItem`). `Design.designData` is editable, so a later edit changes what the admin would read: the invariant "later edits never change what an order prints" does not hold today.
- The admin order detail (`apps/admin/app/admin/orders/[id]/page.tsx`) shows `Design: <name>` and nothing else. `findOneForAdmin` only selects `design: { id, name }`.
- Already in place and reused: `GET /design-assets/:id/link` (short-lived signed link, admins may read any asset, TTW-099) and `GET /design-assets/:id/file` (authenticated bytes).

### Decisions

1. **Freeze at order time.** New nullable column `OrderItem.designSnapshot` (Json, migration generated by the Prisma CLI). Written in the same transaction as the item, from `toOrderItemCreateData`'s callers (standard and campaign orders). Versioned (`version: 1`). Never updated afterwards. Items without a design keep `null`. Images are not copied: an upload never changes once stored. Correction found at review: a `DesignAsset` is deleted with its owner (`onDelete: Cascade`), so an account erasure would remove the originals of a paid order. See "Open risks" below.
2. **Content of the snapshot.** Design id and name, then for every view that holds layers: view key and name, product view id, print area (x, y, width, height as stored), and each layer reduced to an allowlist (image: `designAssetId`, position, scale, angle, flips; text: text, font, size, colour, position, scale, angle). Nothing else from the Fabric JSON is copied.
3. **Admin response.** `GET /admin/orders/:id` adds `items[].printFiles` built from the snapshot only (never from the live design) plus, per image layer, the file facts read from `MediaAsset` (mime, bytes, pixel size) and two stable paths: a display preview and the signed-link endpoint. Response DTO is explicit and documented in Swagger. Customer routes never include it.
4. **Preview.** Drawn in the admin browser from the frozen layers as positioned boxes inside the print area (no Fabric in admin, no server rendering). It is a layout preview for the print shop, not the pixel-exact render that TTW-143 will provide for moderators.
5. **Originals.** A button per image calls `GET /design-assets/:id/link?variant=original` on click, so the link is fresh and never stored or logged.

### Risks and mitigations

- Security: only the admin surface returns `printFiles` (existing `@Roles(ADMIN)` guard on `admin-orders.controller.ts`, test that a customer gets 403). Signed links are minted per click, with the existing TTL cap. No file name, link or customer text goes to logs.
- Data: snapshot is bounded by the existing `TOO_LARGE` limit of the design document, and the allowlist drops everything else.
- Old orders: there are no live users yet, so orders created before this change keep `designSnapshot = null`. The admin shows "Print files were not recorded for this item" for them instead of reading the live design.
- Concurrency: the snapshot is read inside the order-creation transaction, so a save racing with checkout yields either the old or the new design, never a mix. Idempotent replays return the existing order and do not write a second snapshot.

### Out of scope here

- A generated PDF/PNG export per face (the user chose option A). To reopen only if the print shop asks.

## Risks recorded after the first review, and how each ended

- **Originals vanishing with the account.** Not possible today: `Order.user` has no cascade, so a buyer cannot be deleted, and the upload cannot be deleted either. `order-print-files.e2e-spec.ts` pins it. TTW-120 now says it must keep the uploads named by `OrderItem.designSnapshot`. Still a risk for TTW-120, not for this change.
- **Preview text.** Fixed: it wraps inside the stored width and keeps its alignment (checked on a screenshot).
- **Frozen without a second check.** Fixed for standard orders: the orderable check runs again inside the order transaction (unit tests: rejected, no longer the buyer's, vanished). **Not fixed for campaign orders (now TTW-247)**: they follow their own design rule (TTW-239 comment), which this ticket does not change.
- **Opening an original in Safari.** Fixed by design (tab opened on click), plus an http(s) check on the link. Only Chromium was run.
- **Playwright stands in for storage.** Reduced: the signed link now comes from the real API (new private seeded upload, `S3_PRIVATE_BUCKET` set as in the CI workflows). Only the bytes of the on-screen preview are stood in, because the local seed has no stored object.

   - Nit, fixed: http(s) check before opening the signed link.
   - Left as is, said by the reviewer: the customer-leak test calls `OrdersService`, not the HTTP routes (the controller only passes the service result through); no concurrency test on the copy; campaign orders (see above).
   - The reviewer did not run any test.
3. **Second independent review** (another fresh agent, 2026-11-22, read-only, asked to check the first fix and hunt for the same class of defect). Verdict **FAIL** on one major, then fixed:
   - **Major, fixed:** `fontStyle` (italic), which every text of the real editor carries (`TextTool.tsx`), and other styling the validator accepts (underline, overline, line-through, letter spacing, line height, opacity, outline, skew, text background, image crop) were silently dropped from the frozen copy: same class as the `IText` blocker. Fix: the copy now keeps them, skips a layer the customer hid (`visible: false`), and the admin shows italic, decoration, spacing, line height, opacity and mirroring in the preview and says them in words next to it. New safeguard: `order-item-design-snapshot.fields.spec.ts` lists every field the validator accepts (`ACCEPTED_LAYER_FIELDS`) and fails unless each one is deliberately kept or dropped in `SNAPSHOT_KEPT_FIELDS` / `SNAPSHOT_DROPPED_FIELDS`, so a field added to the validator can no longer be lost silently.
   - **Minor, fixed:** a side saved under a key that is no longer the product view key is found by its product view id; a legacy text layer with `content` instead of `text` is kept, and the legacy `layers` list is used when `fabricJson` has nothing to print; the preview mirrors flipped layers and uses Fabric's line height.
   - **Decision, deliberately not applied:** per-character `styles` are left out. The existing test "copies nothing but an allowlist" asserts `styles` never appears, the workshop saves none (it styles a whole text), and the field is listed as dropped with that reason. Revisit if the editor ever offers them.
   - **Not fixed, small:** the in-transaction design recheck and the snapshot read are two reads under READ COMMITTED, so a rejection landing between them is still possible (a tiny window; closing it needs a row lock); nothing in the database enforces that `designSnapshot` is never updated (only the code does); an unknown snapshot version shows the same text as "not recorded".
   - The reviewer did not run any test.
4. **Third independent review** (another fresh agent, 2026-11-22, read-only, focused on the second review's fix; it ran the database-free tests: 3 suites, 84 tests, passing). Verdict **PASS**: no blocker, no major. It checked that every field listed as kept is really copied, that value handling matches what the validator accepts, that a layer cannot print twice or land on the wrong side, and the new preview rendering against Fabric 7 (flip about the box centre, rotation pivot, `charSpacing` in thousandths of an em, line height, no injection path). Minor findings:
   - **Fixed:** the list of kept fields was not tied to what the code copies, so a name could stay listed after its copy was deleted. `order-item-design-snapshot.fields.spec.ts` now builds one layer per kind with a non-default value for every kept field and fails if any is missing from the copy (a new kept field needs a sample), and tests that `visible: false` skips a layer. It passed without a production change, which confirms the reviewer. The stale comment in that spec is corrected.
   - **Not fixed, small, none of it set by the workshop:** the preview does not draw `skewX`, `skewY`, `stroke`, `strokeWidth` or an image's `backgroundColor`, shows `oblique` as normal, and sizes text by `scaleY` only (the data is intact in the copy); a `null` fill is shown as the inherited colour, where Fabric draws nothing; `backgroundColor` and `textBackgroundColor` are both painted on the text box; no automated test checks the flip, opacity or letter-spacing rendering (apps/admin has no unit tests); if `fabricJson` holds only hidden layers, an old design that also carries legacy `layers` falls back to them; a side saved under a key that belongs to another product view is read by key, not by id.
