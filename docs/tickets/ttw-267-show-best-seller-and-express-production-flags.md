# TTW-267 — Show the "Best Seller" badge and the express production tag from product flags

**Epic:** 8 — Client review delivery\
**Status:** In review (implemented, reviewed, committed and merged into local `main`; CI not run)\
**Risk:** High (schema change, admin write, admin screen)\
**Blocked by:** None\
**Blocks:** None

## Background

The Figma frame "Dashboard/Products" shows a "Best Seller" badge on the photo of a product card and a "2-Day Express Production Available" tag under "No Minimum". `Product` has no field for either (`apps/api/prisma/schema.prisma`, `model Product`), so the card shows neither. TTW-204 left the badge out for lack of a rule, and TTW-253 recorded both as "business decision needed".

Product owner decision (2026-11-25): two booleans on the product, both `false` by default, set by hand in the admin. No computation from sales.

## Proposal

1. Schema: `Product.isBestSeller` and `Product.expressProduction`, `Boolean @default(false)`, with a migration generated by the Prisma CLI.
2. API: both fields are optional on admin create and update. They are returned by the customer list and detail and by the admin list and detail. Swagger documents them.
3. Admin: two switches in the "Product details" card, saved with "Save product".
4. Customer card (`/dashboard/products`): a "Best Seller" badge at the top left of the photo (`bg-tamiym-blue`, white text; the theme names this colour for that badge) and a light blue pill with a lightning icon under "No Minimum". Each shows only when its flag is `true`.
5. e2e seed: Classic Tee is a best seller, Campus Hoodie has express production.

Deliberate decisions:

- Strict booleans on write. The global `ValidationPipe` uses implicit conversion, which turns the string `"false"` into `true`. The two new fields keep the raw value, so a string, a number or `null` is refused with 400.
- The lightning icon is an inline SVG, as elsewhere in `apps/app`. No new dependency.
- Switches only on the product edit screen, not on the "New product" form: a new product is a draft with both flags off.
- Rejected: computing "Best Seller" from sales, a free-text badge field, a badge on the product detail page (not requested).

## Invariants

- A product that nobody has flagged shows no badge and no tag.
- Only an admin can change either flag.
- A write that does not send a flag leaves it unchanged.
- The flags are display only: they change no price, stock, delivery time or checkout option.

## Design review

Reviewer: implementing session (Claude), 2026-11-25, before implementation.

- Blast radius: one table (two columns with a default, no backfill needed), admin product create and update, product reads, one admin card, one customer card, e2e seed. Reads that return whole product rows will include the two booleans; they are not sensitive.
- Duplication: no existing flag, tag or badge field on `Product`.
- Interfaces: additive. Requests without the fields behave as before.
- Security: writes stay behind `JwtAuthGuard`, `RolesGuard` and `@Roles(ADMIN)`; the global whitelist refuses the fields on any DTO that does not declare them; draft products stay hidden.
- Edge cases: `"false"` and `null` (refused), partial update (unchanged), flags missing from a response (nothing shown).
- Risks:
  - The tag promises "2-Day Express Production" while the service level is not confirmed (Q39). It is off by default and an admin turns it on per product.
  - The main checkout holds an uncommitted TTW-253 change to the same card (light border, hover shadow). It is not on this branch; it touches lines next to the badge and tag, so whichever is committed second may have a small conflict.
  - TTW-266 edits product option code in `products.service.ts` in parallel: different functions.
  - A server running this code needs the migration applied to its database first, or product reads fail.
- Verdict: proceed once the plan is approved.
